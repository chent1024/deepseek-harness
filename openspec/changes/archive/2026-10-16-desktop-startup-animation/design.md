# Design

A single DesktopStartupAnimation owns the video window, once-per-process random selection, and handoff. The existing Desktop protocol serves only a bundled MP4 and a sandboxed document. It does not load the selection plugin or read its state. The three videos stay local and ship with attribution. The initial 16:9 window scales down within the primary display work area, and contain sizing keeps the complete image visible after resizing. Handoff requires seven seconds from visible playback, the ended signal, and a ready destination. Playback completion before seven seconds cannot shorten that minimum. Welcome uses the same controller through a loaded-window presentation callback.

Desktop starts the window after installing its protocol handler, before reconcileBackend prepares the profile and starts Host. Entering the workspace records a pending reveal without waiting inside startup: the boot IPC currently awaits startup, so waiting there for a client acknowledgement would deadlock. Hidden rendering temporarily disables background throttling until the successful mount acknowledgement arrives. The Web carrier acknowledges after mount and two animation frames, excluding its failure-reporting path.

All window ownership and cleanup remain in the new module. main.ts carries only construction, protocol routing, launch, reveal, recovery/quit, and acknowledgement wiring. Upstream updates should merge into this task branch or its adopted fork branch, preserving these hooks; rebuilding a pure upstream checkout cannot preserve a fork feature. Focused tests exercise delayed mount, full playback, minimum duration, failure, ownership and resource packaging.
